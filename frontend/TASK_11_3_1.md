# Milestone 11.3.1 — Character width and readability

Baseline: `a847e8d07c9149674cdd2a090bf63e0125b59480`. Tracked files were clean;
the user's existing untracked parchment reference remains untouched and unstaged.
The approved parchment layout is preserved. Runtime changes are CSS only.

## Root cause

App already selects `.game-shell-character` for Character, but its shared
`.game-shell` in `styles.css` still applies `max-width: 1440px; margin: auto`.
Character's own 16–44px shell padding and 24–42px sheet padding further reduce
usable space. At a 1920px viewport the capped shell plus padding produces
roughly 280px of dark space on either side. The three-column grid itself is
already flexible and is not the source of the external gutters.

The shared `body { min-width: 320px }` creates a separate narrow-phone problem:
with a vertical scrollbar, the usable width is less than 320px. The original
overflow check against `innerWidth` did not detect content beneath that gutter.

## Exact layout changes

- `.game-shell.game-shell-character`: `max-width: none`, `width: 100%`, outer
  horizontal padding `clamp(12px, 1.5vw, 24px)`. Header, notice and sheet share
  the same alignment. Global shell rules are unchanged.
- `body:has(.game-shell-character)`: remove the shared minimum-width floor
  only while Character is displayed. Other screens retain their body rules.
- Parchment inner padding: `clamp(22px, 2vw, 32px)`; mobile padding 22px.
  Borders, paper texture and ornament dimensions are preserved.
- Portrait: centered with a 380px maximum; original 3:3.9 frame ratio and
  mobile 280px maximum remain. The wider page cannot stretch it excessively.
- Secondary body text: primarily 12px → 13px. Portrait caption 11px → 12px;
  secondary labels/status marks 9px → 10px; achievement names 13px → 14px.
  Font families, main headings and ink colors remain unchanged.
- Read-only badge inset: 40px → 60px to keep it clear of the unchanged upper
  corner ornament after reducing inner padding. Mobile badge remains in flow.

The existing column ratios and 1100px/640px breakpoints are preserved:
three desktop columns, two tablet columns with achievements below, and a
single mobile column. No component, data or interactive state changed.
